# HTTP-сервер - ДЗ 14

Учебный сервер статических файлов на сокетах. Поддерживает GET и HEAD,
индексы каталогов, URL с параметрами и процентным кодированием.
Обработка HTTP написана вручную, сервер использует только стандартную
библиотеку Python.

Условие задания: [homework.pdf](docs/homework.pdf).
Все команды ниже выполняются из `homeworks/14_web_server`.

## Запуск

Проверено на Python 3.14.3 и Windows 11. Для запуска сервера дополнительные
пакеты не нужны.

```powershell
python httpd.py -r ./www
```

Откройте http://127.0.0.1:8080/. Остановка сервера - Ctrl+C.
Остановка и повторный запуск на том же порту проверены пользователем.

Пример с явными параметрами:

```powershell
python httpd.py -r ./www --host 127.0.0.1 --port 8080 --threads 4 --max-queue 8
```

Два рабочих процесса, каждый со своим пулом из четырёх потоков:

```powershell
python httpd.py -r ./www -w 2 --threads 4 --max-queue 8
```

- `-r` - обязательный путь к корневой папке публикуемых файлов.
- `--host` - адрес сервера, по умолчанию `127.0.0.1`.
- `--port` - порт от 1 до 65535, по умолчанию `8080`.
- `--threads` - число рабочих потоков, по умолчанию `4`.
- `--max-queue` - число дополнительных мест ожидания, по умолчанию `8`.
- `-w`, `--workers` - число рабочих процессов, по умолчанию `1`.

Относительный путь `-r` отсчитывается от текущей папки терминала.
Например, `/guide/` соответствует файлу `www/guide/index.html`.
В примере есть короткое пояснение и ссылка на главную страницу.
Сервер работает по HTTP, HTTPS не реализован.

## Архитектура

Родительский процесс создаёт один слушающий сокет и запускает заданное
число рабочих процессов через `multiprocessing` с методом `spawn`.
Рабочие процессы используют общий слушающий сокет, каждый принимает
свои соединения и передаёт их собственному пулу `ThreadPoolExecutor`.
Рабочий поток читает запрос, выбирает файл, формирует ответ и закрывает
клиентское соединение. Родитель HTTP-запросы не обслуживает.

`BoundedSemaphore` ограничивает количество принятых незавершённых задач
суммой `threads + max_queue` в каждом рабочем процессе отдельно.
При значениях по умолчанию это 12 задач на процесс: до 4 выполняющихся
и остальные ожидающие. При `-w 2 --threads 4 --max-queue 8` доступно
до 8 обработчиков и до 24 принятых незавершённых задач суммарно.
Это отдельные пулы и ограничители, общей очереди задач между ними нет.
Если все места заняты, подключения ожидают в очереди ОС.

Лимит заголовков - 65536 байт. Общий срок получения заголовков - 5 секунд;
отдельные порции данных его не продлевают. Таймаут операций клиентского
сокета - 5 секунд, после чтения заголовков он восстанавливается.
Таймаут приёма соединения - 0,5 секунды: worker регулярно
проверяет общий флаг остановки.

Ctrl+C обрабатывает родитель: поднимает `multiprocessing.Event` и ждёт
завершения детей. Они прекращают приём и завершают задачи своих пулов.
Родитель ждёт каждый процесс до 10 секунд; оставшийся живым процесс
завершается принудительно. Неожиданный выход worker вызывает ошибку
и остановку остальных процессов. Автоматический перезапуск не реализован.

GET и HEAD возвращают 200, 403 или 404. Остальные методы получают 405
с заголовком `Allow: GET, HEAD`. Выход за корневую папку запрещён.
Для каталога без `index.html` возвращается 404. HEAD передаёт заголовки
без тела. Каждое соединение обслуживает один запрос (`Connection: close`).

GET передаёт файлы порциями до 65536 байт. HEAD получает размер открытого
файла через fstat и не читает тело. Передача файлов размером 2 ГБ и более
не проверялась.

## Структура

- `httpd.py` - сервер и параметры командной строки.
- `www` - примеры публикуемых файлов.
- `tests/test_httpd.py`, `tests/test_server.py` - собственные тесты.
- `tests/examples/competitiveness.py` - ручная проверка двух клиентов.
- `tests/http-test-suite-master` - внешний набор из условия ДЗ.
- `tests/load_testing` - результат нагрузки, журнал сервера и диагностика
  последнего запуска.
- `docs/examples/webserver_skeleton.py` - исходный учебный пример,
  основной сервер его не использует.

## Тесты

Для собственных тестов нужен pytest. В активированном окружении:

```powershell
python -m pip install pytest
python -m pytest -q tests
```

Полный набор при проверке 10.11.2026 - **128 passed**. Проверяются чтение
заголовков, разбор запроса, пути, HTTP-ответы, параметры запуска,
конкурентная обработка, ограничение задач и освобождение ресурсов.
Дополнительно проверяются общий срок чтения заголовков, синтаксис строки
запроса, передача файлов порциями, HEAD без чтения тела и запись
неожиданных ошибок с traceback. При некорректной строке запроса
соединение закрывается; отдельные ответы 400/505 не реализованы.
Интеграционные тесты запускают собственные серверы на свободных портах.
Проверки ссылок имитируют результат `Path.resolve` и не требуют
специальных прав Windows. Отдельные проверки запускают два настоящих
процесса через `spawn`, проверяют общий сокет, суммарное ограничение
задач, завершение по Event и освобождение порта.

Внешний набор: [s-stupnikov/http-test-suite](https://github.com/s-stupnikov/http-test-suite).
В первом терминале:

```powershell
python httpd.py -r ./tests/http-test-suite-master --port 80
```

Во втором терминале:

```powershell
python ./tests/http-test-suite-master/httptest.py
```

Адрес `localhost:80` задан внутри внешнего скрипта. Результат -
**23 теста, OK**, последняя проверка 10.11.2026 на текущем коде
с двумя рабочими процессами. Предупреждения SyntaxWarning и DeprecationWarning
относятся к старому синтаксису внешнего скрипта.

Тестовая страница `/httptest/wikipedia_russia.html` проверена
пользователем в браузере: картинки и оформление отображаются.

Ручная проверка конкурентности выполняется при работающем сервере
на порту 8080 с двумя или более потоками:

```powershell
python tests/examples/competitiveness.py
```

## Нагрузочное тестирование

Последняя проверка - 09.11.2026, ApacheBench 2.3 для Windows.
Нагрузочный результат получен до перехода к передаче файлов порциями.
Сервер и клиент запускались на одном компьютере. Сервер: 2 рабочих
процесса, по 4 потока и 8 мест ожидания в каждом, папка `www`.
Запрашивался `/`, размер тела ответа - 215 байт. Использовался отдельный
порт 18080. Вывод сервера и ApacheBench записывался напрямую в файлы,
без конвейера PowerShell.

Запуск сервера:

```powershell
python httpd.py -r ./www --port 18080 -w 2 --threads 4 --max-queue 8
```

Команда нагрузки:

```powershell
& 'D:\tools\Apache24\bin\ab.exe' -n 50000 -c 100 -r http://127.0.0.1:18080/
```

Результат последнего запуска:

- Завершено запросов: 50000, ошибок: 0.
- Конкурентных клиентов: 100.
- Общее время: 22,253 секунды.
- Скорость: 2246,87 запроса/с.
- Среднее время запроса по расчёту ApacheBench: 44,506 мс.
- 95% запросов завершились за 60 мс, 99% - за 78 мс.
- Максимальное время запроса: 145 мс.

В репозитории для сдачи ДЗ сохраняются три файла последнего запуска:

- [benchmark.txt](tests/load_testing/benchmark.txt) - полный отчёт
  ApacheBench: 50000 запросов, 100 конкурентных клиентов, 0 ошибок.
- [server.log](tests/load_testing/server.log) - журнал сервера
  в UTF-8, около 3 МБ.
- [diagnostics.log](tests/load_testing/diagnostics.log) - параметры
  запуска, снимки TCP-состояний и сведения об остановке тестовых процессов.

После измерения тестовое дерево процессов было остановлено принудительно;
штатная остановка по Event проверяется отдельными интеграционными тестами.

Результат относится к этому локальному запуску и небольшому файлу.
Это не измерение скорости передачи больших файлов.

В предыдущем запуске на порту 8080 через конвейер PowerShell наблюдалась
длинная пауза и 5 ошибок подключения. В изолированной повторной проверке
пауза не воспроизвелась, несмотря на большое число TIME_WAIT.
Причина прежней паузы не установлена: изменились и порт, и способ вывода.
