# Бронирование столов - ДЗ 11

Учебный проект по DDD и чистой архитектуре. Доработан пример бронирования
столов из материалов занятия. Практика SOLID находится в соседнем каталоге
[SOLID](../SOLID/).

## Что реализовано

- Создание подтверждённой брони и отмена по идентификатору.
- Модель стола Table и отдельный репозиторий столов.
- Выбор свободного стола с наименьшей подходящей вместимостью.
- Поиск пересекающихся броней. Подтверждённая бронь занимает стол,
  отменённая его не блокирует. Конец одной брони может совпадать с началом другой.
- Общий Unit of Work для столов и броней. commit подтверждает изменения,
  rollback восстанавливает оба репозитория из глубокого снимка.
  Выход без commit и исключение до подтверждения вызывают откат.

Количество гостей и вместимость стола должны быть положительными,
конец бронирования - позже начала. Подтверждение требует назначенного стола.
Завершённую бронь отменить нельзя. Повторная отмена не добавляет новое событие.

## Структура

- `src/booking/domain` - модель, правила, события, фабрика, выбор стола
  и контракты репозиториев.
- `src/booking/application` - команды, обработчики создания и отмены,
  контракт Unit of Work.
- `src/booking/infrastructure` - репозитории и Unit of Work в памяти.
- `src/booking/entrypoints` - закомментированный пример HTTP-обработчика.
- `tests` - проверки модели, сценариев, репозиториев, отката и конфликтов бронирования.

Reservation хранит состояние одной брони. ReservationAggregate управляет
её изменениями и записывает события. Фабрика подготавливает данные для создания,
обработчик получает столы из репозитория и исключает занятые. Сервис выбора
сравнивает вместимость оставшихся столов.

## Окружение и тесты

Нужны uv и Python. В pyproject.toml указана поддержка Python 3.10+,
текущая версия проверена на Python 3.14.3.
Команды выполняются из каталога `project`.

```powershell
uv sync --python 3.14 --extra dev
uv run --extra dev python -m pytest
```

Зависимости описаны в pyproject.toml, точные версии закреплены в uv.lock.
Окружение создаётся в `.venv`. Дополнительный набор dev включает pytest и ruff.

На последней проверке: 37 passed. Проверяются создание и отмена брони,
выбор другого стола при конфликте, смежные интервалы, освобождение после отмены,
сохранение и совместный откат столов и броней.

## Ограничения

Данные хранятся в памяти процесса и теряются при его завершении.
События находятся в списках агрегатов, отдельно не сохраняются и не отправляются.

Сценарии вызываются из тестов. SQLAlchemy и HTTP оставлены заготовками,
работающего сервера нет. Конфликты проверяются для последовательных запросов;
защита от одновременного бронирования параллельными запросами не реализована.
