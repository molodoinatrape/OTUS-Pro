# Анализатор логов

Учебный проект курса OTUS «Python Developer. Professional».

Программа выбирает самый свежий nginx-лог по **дате в имени**,
рассчитывает статистику по URL и создаёт HTML-отчёт.

## Возможности

- Чтение обычных и gzip-логов
- Выбор последнего лога по дате в имени
- Расчёт количества запросов и временных метрик по каждому URL
- Отбор URL с наибольшим суммарным временем обработки
- Создание HTML-отчёта
- Настройка через JSON-файл и аргумент --config
- Запись событий и ошибок в формате JSON в терминал или файл

Если найден обычный и gzip-лог с одинаковой датой, используется обычный файл.

## Требования

- Python 3.14
- Poetry для работы с исходниками и сборки пакета; для установки готового wheel достаточно pip
- Браузер для просмотра HTML-отчёта
- Доступ к интернету при просмотре отчёта: шаблон загружает jQuery с внешнего сервера

## Установка

После клонирования репозитория перейдите из его корня в папку проекта:

```shell
cd homeworks/01_log_analyzer
```
Установите зависимости:

```shell
poetry install
```

Команды для работы с исходниками выполняются из _homeworks/01_log_analyzer_.
Для установки готового wheel ниже указан отдельный рабочий каталог.

Проект имеет собственные pyproject.toml, poetry.lock и виртуальное окружение.
Если в терминале активно окружение другого проекта, сначала выйдите из него.

## Сборка и установка wheel

Из каталога `homeworks/01_log_analyzer` выполните:

```shell
poetry check --lock
poetry build
```

В `dist` появятся архив исходников `otus_pro-0.1.0.tar.gz` (sdist)
и пакет для установки `otus_pro-0.1.0-py3-none-any.whl` (wheel).
HTML-шаблон и JavaScript включены в оба формата. Сборка сама по себе не устанавливает пакет.

Пример установки в отдельное окружение через PowerShell. Первые две команды
выполняются из каталога проекта; все команды — в одном окне терминала:

```powershell
$wheelPath = (Resolve-Path "dist/otus_pro-0.1.0-py3-none-any.whl").Path
poetry run python -m venv D:\database\log-analyzer-wheel-check\.venv
Set-Location D:\database\log-analyzer-wheel-check
.\.venv\Scripts\python.exe -m pip install $wheelPath
.\.venv\Scripts\log-analyzer.exe --help
```

Каталог `D:\database\log-analyzer-wheel-check` можно заменить своим.
При изменении версии проекта используйте соответствующее имя wheel.
pip устанавливает рабочие зависимости по метаданным пакета.
Poetry для запуска установленной программы не требуется.

В рабочем каталоге рядом с `.venv` создайте `logs` с входными nginx-логами
и файл `config.json`:

```json
{
  "LOG_DIR": "logs",
  "REPORT_DIR": "reports",
  "REPORT_SIZE": 10,
  "PARSE_ERROR_THRESHOLD": 0.5
}
```

Запустите из этого рабочего каталога:

```powershell
.\.venv\Scripts\log-analyzer.exe
$LASTEXITCODE
```

Для другого файла конфигурации используйте
`.\.venv\Scripts\log-analyzer.exe --config .\custom.json`.
Шаблоны берутся из установленного пакета. Готовые HTML-отчёты и JavaScript
сохраняются в `reports`. Код `0` означает успешное завершение;
наличие нового отчёта проверяйте отдельно, поскольку отсутствие подходящих логов
также завершается с кодом `0`.

После изменения исходников пересоберите wheel. Если версия осталась прежней,
для обновления установленной копии выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install --force-reinstall $wheelPath
```

Переменная `$wheelPath` должна содержать полный путь к обновлённому wheel.
Для проверки создания нового отчёта выберите новый `REPORT_DIR`:
существующий отчёт анализатор повторно не создаёт.

## Быстрый запуск

Для тестового запуска на маленьком логе используйте готовую конфигурацию:
```shell
poetry run python log_analyzer.py --config config.logging.json
```

Она использует лог из _tests/sample_ и сохраняет результаты:

    reports/report-2017.06.29.html
    reports/jquery.tablesorter.min.js
    logs/analyzer.jsonl

Откройте HTML-файл в браузере. Нажатие на заголовок столбца меняет
порядок сортировки.

В этой конфигурации сообщения программы записываются в файл:

    logs/analyzer.jsonl

## Обработка собственных логов

Создайте каталог logs и поместите в него файлы с именами вида:

    nginx-access-ui.log-20170630
    nginx-access-ui.log-20170630.gz

Формат имени:

    nginx-access-ui.log-YYYYMMDD[.gz]

Дата должна быть корректной календарной датой. Файлы с другими именами
не участвуют в выборе лога.

Содержимое должно соответствовать ожидаемому nginx-формату:
URL извлекается из поля запроса в кавычках, время обработки - из последнего поля строки.

Запустите анализатор:

```shell
poetry run python log_analyzer.py
```

Без аргумента `--config` программа читает `config.json` из текущего рабочего каталога,
из которого запущена команда. Относительные пути в конфигурации также отсчитываются
от рабочего каталога, а не от расположения JSON-файла или установленного модуля.
Если конфигурация отсутствует или некорректна, программа завершается с ошибкой.

В текущем _config.json_ задано:

```json
{
  "REPORT_SIZE": 10
}
```

Остальные значения берутся из настроек по-умолчанию в коде.

Большие входные логи и сгенерированные отчёты не хранятся в Git.

## Конфигурация

Путь к другому файлу настроек передаётся через --config:

```shell
poetry run python log_analyzer.py --config config.logging.json
```

Пример полной конфигурации:

```json
{
  "LOG_DIR": "tests/sample",
  "REPORT_DIR": "reports",
  "REPORT_SIZE": 10,
  "LOG_FILE": "logs/analyzer.jsonl",
  "PARSE_ERROR_THRESHOLD": 0.5
}
```

### Параметр - Назначение - Значение по-умолчанию в коде

**LOG_DIR** - Каталог входных nginx-логов - "logs"
**REPORT_DIR** - Каталог готовых отчётов - "reports"
**REPORT_SIZE** - Максимальное количество URL в отчёте - 1000
**LOG_FILE** - Путь к журналу работы анализатора - Не задан: вывод в терминал
**PARSE_ERROR_THRESHOLD** - Порог ошибок (от 0 до 1 включительно)

Правила настройки:

- Значение из JSON-файла имеют приоритет над значениями по-умолчанию
- Можно переопределить не все параметры
- Пустой файл или {} оставляет настройки по умолчанию
- Непустой файл должен быть JSON
- Значения путей должны быть непустыми строками
- REPORT_SIZE должен быть положительным целым числом
- Строка "10" и логическое значение TRUE не принимаются вместо числового REPORT_SIZE
- Неизвестные параметры отклоняются
- При превышении порога ошибок - ошибка и код 1, отчёт не создаётся
- Порог по умолчанию - 0.5 (50%), проверяется после полного чтения
- Для пересчёта нужно убрать существующий отчёт

Справка по аргументам:

```shell
poetry run python log_analyzer.py --help
```

## Отчёт

### Поле - Значение

**url** - Адрес запроса
**count** - Количество запросов
**count_perc** - Доля запросов URL от общего количества, в процентах
**time_sum** - Суммарное время обработки
**time_perc** - Доля времени URL от общего времени, в процентах
**time_avg** - Среднее время обработки
**time_max** - Максимальное время обработки
**time_med** - Медианное время обработки

    Если отчёт для выбранного лога уже существует - повторный не создаётся.

Временные метрики измеряются в секундах.

Имя отчёта содержит дату обработанного лога:

    reports/report-YYYY.MM.DD.html

Например:

    reports/report-2017.06.30.html

Для создания отчёта используются файлы из _templates_:

- **report.html** - HTML-шаблон
- **jquery.tablesorter.min.js** - плагин сортировки таблицы

## Логирование и ошибки

Программа использует _structlog_ и записывает события в формате _JSON_.

Если _LOG_FILE_ отсутствует, сообщения выводятся в терминал.
Если путь указан, сообщения дописываются в JSONL-файл в кодировке _UTF-8_.

Пример события:

    {"event": "Анализатор запущен", "level": "info", "timestamp": "2026-09-12T14:08:44Z"}

В событиях содержатся:

|                         |                       |
|-------------------------|-----------------------|
| event                   | описание события      |
| level                   | уровень сообщения     |
| timestamp               | время UTC             |
| exception               | traceback при ошибке  |
| дополнительные<br/>поля | например, report_path |

Повторный запуск сохраняет предыдущие сообщения и добавляет новые.

### Коды завершения

- 0 - Успешное завершение, включая отсутствие подходящих логов
- 1 - Ошибка обработки или прерывание через Ctrl+C
- 2 - Ошибка аргументов командной строки, обнаружен argparse
